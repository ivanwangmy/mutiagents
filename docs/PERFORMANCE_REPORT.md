## 7. 性能瓶颈与观察

1. **上下文重复携带**：每轮发言都重新发送公开消息，双/三 Agent 的 prompt token 随轮次增长，是耗时与成本的主因。
2. **预算预检偏保守**：`上下文估算 + 800 输出 + 200 余量` 使多 Agent 任务在约 8—9k token 时提前终止，保证安全但牺牲了自然结束。
3. **串行模型调用**：Agent 逐个发言，双 Agent 3 次调用约 10 秒，符合串行链路预期。
4. **前端无额外轮询开销**：课堂页由 SSE 驱动，浏览器仅保留必要的一次任务详情请求。
5. **数据库与事件开销可忽略**：917 条任务事件下，接口响应正常；工具执行耗时远小于模型耗时。

## 9. 结论

- 性能【已完成】：单 Agent 约 4 秒、双 Agent 约 11 秒、三 Agent 约 7 秒，全部在可接受范围。
- 成本【已完成】：18 个真实任务共消耗约 11 万 token，单任务均值约 6.1k，输出受上限保护。
- 预算控制【部分完成】：安全有效，但默认预算下多 Agent 更容易由 `token_budget` 终止；如需"讨论到自然结束"，需调高预算或压缩上下文。
- 稳定性【已完成】：0 失败、0 超时（沙箱故意死循环除外，且被 5s 正确终止）。
