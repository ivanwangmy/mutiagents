# 第 6 轮：多 Agent 自主协作系统

本轮实现 AI 智播课堂最核心的能力。

三个 Agent 必须能够在同一个对话任务中真实协作。

## 一、参与者管理

用户选择：
- 一个 Agent。
- 任意两个 Agent。
- 三个 Agent。

selected_agent_ids 是强制约束。

任何未被选择的 Agent 不得加入任务。

## 二、Message Bus

建立真实消息总线。

消息字段至少包括：

- message_id
- conversation_id
- task_id
- sender_agent_id
- receiver_agent_id
- message_type
- content
- reply_to_message_id
- timestamp
- metadata

支持：
- message
- question
- response
- challenge
- request_help
- handoff
- conclusion

## 三、动态调度

建立 Discussion Manager。

它负责：
- 维护任务状态。
- 管理参与者。
- 分发消息。
- 控制任务预算。
- 管理终止条件。
- 记录事件。

它不能代替 Agent 思考。

Agent 必须根据当前上下文自主决定是否发言和回应。

优先使用 LangGraph 当前版本支持的动态调度机制，例如 Send、Command、子图等。

具体实现前先核对官方文档。

不要强行构建固定的 Alex→Mia→Ethan 循环。

## 四、Agent 自主决策

每次执行时，Agent 可以选择：

- RESPOND：直接回应。
- ASK_USER：向用户提出问题。
- MESSAGE_AGENT：向其他 Agent 发送消息。
- REQUEST_HELP：向其他 Agent 请求帮助。
- CHALLENGE：对其他观点提出质疑。
- USE_TOOL：调用工具。
- WAIT：等待。
- FINISH：结束当前参与。

这些是行为选择，不是固定执行顺序。

必须设置：
- 最大执行轮次。
- 最大消息数量。
- 最大模型调用次数。
- 总执行时间。
- 任务 Token 或成本预算。

避免无休止讨论。

## 五、消息理解

Agent 必须能够理解：
1. 当前用户问题。
2. 其他 Agent 的观点。
3. 当前讨论进度。
4. 自己之前的发言。
5. 其他 Agent 对自己的回应。

回应其他 Agent 时，尽量明确引用对应观点，避免泛泛而谈。

## 六、验收场景

场景一：只选择 Alex。

只有 Alex 回答，其他 Agent 不得出现。

场景二：选择 Alex 和 Ethan。

Alex 进行理论分析，Ethan 根据自己的理解提出问题或观点。

场景三：选择三个 Agent。

三个 Agent 根据问题自主决定参与程度。

场景四：观点存在分歧。

Agent 能够指出具体分歧，并给出理由。

场景五：讨论没有必要继续。

Agent 可以合理结束，不强制所有人发言。

所有测试必须使用真实模型调用和真实 Message Bus。
