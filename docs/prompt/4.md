# 第 4 轮：统一模型接入与单 Agent 运行

本轮实现真正可运行的单 Agent 对话系统。

## 一、模型供应商适配层

建立统一接口：

ModelProvider
ModelConfig
ModelRegistry
ModelResponse
ModelStreamResponse

支持通过配置切换模型供应商和模型名称。

API Key 通过环境变量读取。

不得将密钥暴露到前端。

## 二、模型能力验证

必须实际验证：
- 文本生成。
- 流式输出。
- 原生 Tool Calling。
- 结构化输出。

不能仅凭模型名称推断其支持能力。

## 三、Agent Runtime

建立：
- AgentExecutor
- AgentGraphFactory
- AgentState
- AgentExecutionContext

每个 Agent 必须加载自己的 Prompt 和配置。

## 四、对话接口

实现：

POST /api/conversations

GET /api/conversations

GET /api/conversations/{id}

POST /api/conversations/{id}/messages

GET /api/conversations/{id}/messages

建立基础对话生命周期。

## 五、实现单 Agent 测试

分别测试：
- 仅 Alex。
- 仅 Mia。
- 仅 Ethan。

要求：
1. 用户可以连续提问。
2. Agent 能理解上下文。
3. Agent 保持自身人格。
4. 支持流式输出。
5. 能正确处理中断、超时和模型错误。

本轮暂时不实现多 Agent 协作。

## 六、验收

必须使用真实模型 API 完成实际对话。

如果缺少 API Key，应明确标记模型联调未完成，不允许用模拟数据冒充成功。
