## 4. Python 沙箱逃逸 【已完成】

直接调用线上使用的真实实现 `app.tools.builtin.python_sandbox.run_python`：

| 攻击载荷 | 结果 |
| --- | --- |
| `open('C:/Windows/win.ini')` | 验证阶段拦截 |
| `import os` 读取环境变量 | 验证阶段拦截 |
| `(1).__class__.__bases__` | 验证阶段拦截（双下划线） |
| `exec('print(1)')` | 验证阶段拦截 |
| `while True: pass` | 5.1 秒后 `SandboxValidationError: 执行超时（>5.0 秒）` |

- 正常代码实测可用：1..100 求和返回 `5050`，耗时 398ms。
- 隔离参数：独立子进程、5 秒超时、256MB 内存上限、受限内置名与导入白名单。
- 残余风险：沙箱为进程级隔离而非容器级隔离，CPU/文件系统层面仍有理论攻击面；不建议对不可信公网用户开放任意 Python 执行。

## 8. 超时与资源限制 【部分完成】

- 沙箱：死循环 5.1 秒被终止，【已完成】。
- 任务级上限（接口实测）：`task_token_budget=12000`、`task_max_model_calls=8`、`task_max_messages=12`、`task_max_turns=10`、`task_max_seconds=120`、`max_output_tokens=800`、`max_context_tokens=3000`。
- 实际触发：多个多 Agent 任务以 `stop_reason=token_budget` 结束，证明预算限制真实生效。
- 用户停止：`POST /api/tasks/{id}/stop` → `status=stopped`，浏览器点击"停止生成"同样生效，【已完成】。
- 120 秒自然超时未构造（避免无意义长时间占用），标记【未验证】。

| 风险 | 等级 | 状态 | 建议 |

| 无身份认证与权限体系 | 高（公网部署时） | 【未完成】 | 公网部署前增加登录、会话与资源级授权；当前仅限本地或受信内网 |
